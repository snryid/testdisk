# RFC 0005：跨平台格式化

状态：通过
创建日期：2026-07-02
负责人：Beck

## 摘要

将当前 macOS 外置磁盘格式化扩展为跨平台、安全门禁保护的格式化工作流，支持外置/可移动磁盘和受支持卷。

## 目标

- 支持 macOS、Linux 和 Windows 上的外置/可移动整盘格式化。
- 只提供当前平台和目标支持的文件系统。
- 增加卸载、格式化、验证和重新扫描步骤。
- 记录每一次破坏性操作。

## 文件系统矩阵

| 文件系统 | macOS | Linux | Windows |
|----------|-------|-------|---------|
| APFS | 支持 | 不支持 | 不支持 |
| HFS+ | 支持 | 可选 | 不支持 |
| ExFAT | 支持 | 支持 | 支持 |
| FAT32 | 支持 | 支持 | 支持 |
| NTFS | 无安全原生格式化 | 可选 | 支持 |
| ext4 | 不支持 | 支持 | 不支持 |

## 后端要求

- 每次格式化命令执行前重新分类目标。
- 拒绝内置/系统/未知磁盘。
- 整盘格式化时拒绝分区目标。
- 使用结构化进程参数，不做 shell 字符串拼接。
- 保存操作计划和结果。

## UI 要求

- 执行前展示目标、文件系统、卷名和风险。
- 要求输入与目标 ID 匹配的确认文本。
- 要求原生确认对话框。
- 完成后刷新磁盘元数据。

## 验收标准

- 格式化测试只使用 mock 命令执行器或临时镜像。
- UI 不展示不支持的文件系统。
- 即使绕过前端，后端也会阻止不安全目标。
- 操作结果包含命令计划、状态、stdout/stderr 摘要和后置检查状态。

## 开放问题

- Linux 应依赖已安装的 `mkfs.*` 工具，还是打包辅助二进制？
- Windows 第一版应使用 PowerShell，还是直接使用 Win32 API？
