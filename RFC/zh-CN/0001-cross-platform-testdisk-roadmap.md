# RFC 0001：Mini TestDisk 跨平台路线图

状态：通过
创建日期：2026-07-02
负责人：Beck

## 摘要

本文档定义 Mini TestDisk 的分阶段演进路线：从当前 Tauri + Rust 可行性原型，逐步发展为一个受 TestDisk 启发的跨平台磁盘分析、恢复和维护工具。路线图要求每项功能都能在 macOS、Linux 和 Windows 上保持一致的产品语义，同时通过明确的平台适配层隔离不同操作系统的磁盘访问差异。

项目不应一次性复刻 TestDisk 和 PhotoRec 的全部能力。第一目标是建立安全、可测试的架构：先实现各平台一致的只读分析能力，再加入受约束的写入操作，最后扩展到更深入的恢复工作流。

## 目标

- 提供用于磁盘、分区和文件系统检查的跨平台 GUI。
- 支持 macOS、Linux、Windows 上的物理磁盘和磁盘镜像。
- 分阶段加入恢复和修复能力，并为每个阶段设置明确的安全门禁。
- 将破坏性操作隔离为可审计、可确认、可回滚或可验证的流程。
- 在 Rust 中沉淀可复用核心逻辑，用轻量平台适配器处理设备枚举、权限、挂载、格式化和写入操作。

## 非目标

- 不盲目复制 TestDisk 的 ncurses 交互流程。
- 不提供不受限制的系统盘写入能力。
- 初期路线图不包含内核扩展或自定义驱动。
- 当宿主平台已有更安全的原生命令时，不重新实现专有文件系统修复逻辑。
- 不在分区修复同一阶段实现 PhotoRec 级别的文件雕刻能力。

## 当前状态

当前已实现能力：

- Tauri 桌面外壳和 Vue 前端。
- 磁盘/镜像选择 UI。
- 面向 macOS/Linux 的磁盘枚举。
- 磁盘镜像打开。
- MBR 和 GPT 检测。
- GPT 头 CRC 校验。
- 常见文件系统签名检测。
- 简化的 1 MB 对齐丢失分区扫描。
- macOS 外置/USB 整盘格式化，支持 APFS、ExFAT、FAT32 和 HFS+。

当前缺口：

- 尚未实现 Windows 磁盘枚举和原始磁盘访问。
- 尚未实现 Linux 格式化和权限处理。
- 磁盘元数据较少，内部/外部/可移动/协议等信息尚未统一建模。
- 没有持久化扫描报告。
- 没有分区表重建方案工作流。
- 没有分区表写回修复路径。
- 没有引导扇区备份/恢复。
- 没有删除文件恢复。
- 没有 SMART 或磁盘镜像制作工作流。
- 没有脚本化或批处理模式。

## 设计原则

### 跨平台优先

每个用户可见功能在实现前都必须定义 macOS、Linux 和 Windows 上的行为。如果某项能力依赖平台工具，对应 RFC 必须列出每个操作系统使用的命令/API，以及不支持时的表现。

### 先读后写

每个写入功能都必须先具备只读预览模式。用户必须能在任何磁盘变更前看到准确目标、计划操作、风险级别和预期结果。

### 明确设备模型

核心层应分别建模磁盘、分区、卷和镜像：

- 磁盘：完整物理或虚拟设备。
- 分区：带字节/LBA 范围的分区表条目。
- 卷：可挂载的文件系统实例。
- 镜像：作为磁盘处理的普通文件。

### 原生适配，共享核心

分区解析、签名检测、扫描计划和结果建模应位于 `testdisk-core`。操作系统特定访问应隐藏在适配器 trait 后，由 Tauri 命令层或独立平台 crate 调用。

### 默认安全

危险操作必须要求：

- 目标分类；
- 非系统盘保护；
- dry-run 计划；
- 输入式确认；
- 操作日志；
- 操作后验证。

## 建议架构

```text
ui/
  Vue 工作流面板
  扫描结果
  恢复计划
  破坏性操作确认

src-tauri/
  IPC 命令
  平台适配器选择
  权限和原生命令编排

crates/testdisk-core/
  分区解析器
  文件系统检测器
  扫描引擎
  恢复计划模型
  校验和安全检查

crates/testdisk-platform/      [新增]
  macOS diskutil 适配器
  Linux lsblk/blkid/mkfs 适配器
  Windows WMI/PowerShell/Win32 适配器
```

## 平台适配目标

| 能力 | macOS | Linux | Windows |
|------|-------|-------|---------|
| 磁盘枚举 | `diskutil list/info -plist` | `lsblk --json`、`/sys/block` | WMI / PowerShell `Get-Disk`、Win32 API |
| 原始读取 | `/dev/rdiskN` | `/dev/sdX`、`/dev/nvmeXnY` | `\\.\PhysicalDriveN` |
| 文件系统元数据 | `diskutil info -plist` | `blkid`、`lsblk -f` | WMI / PowerShell `Get-Volume` |
| 挂载/卸载 | `diskutil mount/unmountDisk` | `udisksctl`、`mount`、`umount` | PowerShell `Mount-Volume`、`Dismount-Volume` |
| 格式化 | `diskutil eraseDisk/eraseVolume` | `mkfs.*`、`parted` | PowerShell `Format-Volume`、`Clear-Disk` |
| SMART | 可选 `smartctl` | 可选 `smartctl` | 可选 `smartctl` / WMI 有限支持 |
| 镜像制作 | Rust 核心读写器 | Rust 核心读写器 | Rust 核心读写器 |

## 分阶段路线图

### 阶段 0：基础加固

目的：让当前原型成为可靠的跨平台基础。

功能：

- 增加标准化磁盘模型，字段包括来源、平台 ID、显示名称、协议、内部/外部、可移动、大小、读写能力和风险级别。
- 将平台访问逻辑从 `disk.rs` 拆出，放到平台适配器边界之后。
- 增加 Windows 磁盘/镜像读取支持。
- 增加 Linux 磁盘元数据和权限检测。
- 增加一致的错误类型：权限不足、设备忙、不支持的平台、非法目标、命令失败。
- 增加 JSON 扫描报告导出。

验收标准：

- 同一套 UI 可以在 macOS、Linux 和 Windows 上枚举磁盘。
- 磁盘镜像在三个平台上都可使用。
- 单元测试覆盖目标规范化和安全分类。
- 本阶段不增加写入操作。

### 阶段 1：分析能力对齐

目的：增强类似 TestDisk 的只读诊断能力。

功能：

- 扩展分区表支持：MBR、GPT、混合 MBR、扩展/逻辑分区。
- 检测分区表不一致并生成警告。
- 检测备份 GPT，并比较主 GPT 与备份 GPT 头。
- 改进深度扫描，不再只依赖固定 1 MB 边界。
- 为发现的分区增加置信度评分。
- 增加 FAT12/16/32、exFAT、NTFS、ext2/3/4、APFS、HFS/HFS+、UFS 等文件系统的详细探测能力。
- 增加“当前分区表 vs 发现候选项”的并排 UI。

验收标准：

- 扫描结果包含置信度、来源、重叠状态和修复建议。
- 当文件系统签名存在时，深度扫描可以找到并非严格 1 MB 对齐的分区。
- 对镜像文件的只读分析无需提升权限即可使用。

### 阶段 2：安全格式化和卷操作

目的：把原型中已开始的格式化功能补齐为跨平台能力。

功能：

- 跨平台外置/可移动整盘格式化。
- 在平台支持时提供跨平台分区/卷格式化。
- 文件系统列表按平台和目标类型过滤。
- 格式化前卸载工作流。
- 格式化后验证和自动重新扫描。
- 操作日志以 JSON 保存。

文件系统目标矩阵：

| 文件系统 | macOS | Linux | Windows |
|----------|-------|-------|---------|
| APFS | 支持 | 无原生格式化 | 不支持 |
| HFS+ | 支持 | 依赖可选工具 | 不支持 |
| ExFAT | 支持 | 依赖工具支持 | 支持 |
| FAT32 | 支持 | 支持 | 支持 |
| NTFS | 无安全原生格式化 | 依赖可选工具 | 支持 |
| ext4 | 不支持 | 支持 | 不支持 |

验收标准：

- UI 不展示当前平台适配器不支持的文件系统。
- 内置/系统磁盘由后端校验阻止。
- 格式化必须输入式确认，并返回结构化操作结果。

### 阶段 3：恢复计划构建器

目的：允许用户先构建分区恢复方案，但暂不写盘。

功能：

- 选择发现的分区加入恢复计划。
- 校验重叠、顺序、磁盘边界和分区表约束。
- 在内存中生成建议的 MBR 或 GPT 表。
- 展示分区图 before/after 对比。
- 导出恢复计划 JSON。
- 导入恢复计划 JSON 进行复核。

验收标准：

- 本阶段不发生任何磁盘写入。
- 非法计划会被拒绝，并给出可执行的错误信息。
- 计划生成结果具有确定性，并通过快照测试覆盖。

### 阶段 4：分区表写回

目的：实现类似 TestDisk 的分区表修复能力，并带强保护。

功能：

- 将 MBR 或 GPT 恢复计划写入选定目标。
- 写入前强制备份原始扇区。
- 支持从备份恢复。
- 在适用平台上要求目标离线/已卸载。
- 写入后重新读取并比较验证。
- 保留完整操作记录。

验收标准：

- 没有有效阶段 3 计划时，不能执行写回。
- 除非平台适配器能证明安全，否则应用拒绝写入已挂载/系统磁盘。
- 在磁盘镜像测试中，恢复备份可以还原原始扇区。

### 阶段 5：引导扇区和文件系统修复辅助

目的：增加常见 TestDisk 修复辅助能力，但不重写完整文件系统修复引擎。

功能：

- 在布局明确时比较/恢复 FAT 引导扇区备份。
- 在安全时比较/恢复 NTFS 引导扇区备份。
- 提供 ext superblock 发现提示。
- 通过原生工具提供 APFS/HFS+ 修复指引。
- 提供“运行原生修复命令”的适配器钩子，并带预览。

验收标准：

- 每个修复辅助能力都有只读诊断模式。
- 执行任何原生修复命令前都必须展示命令。
- 未通过操作后检查时，应用不能宣称修复成功。

### 阶段 6：文件恢复和删除恢复

目的：在磁盘/分区工作流稳定后，增加文件级恢复流程。

功能：

- 对已实现元数据解析的文件系统提供目录树浏览。
- 对安全可解释元数据的文件系统列出删除文件。
- 将选中的文件恢复到另一个目标磁盘。
- 默认禁止将文件恢复到源磁盘。

验收标准：

- 目标路径必须不同于源目标。
- 恢复过程对源磁盘保持只读。
- 部分恢复失败时按文件返回错误。

### 阶段 7：PhotoRec 风格文件雕刻

目的：将基于签名的文件雕刻作为独立于分区恢复的工作流加入。

功能：

- 扫描原始扇区中的文件签名。
- 选择文件类型族。
- 将雕刻出的文件恢复到目标目录。
- 支持中断后恢复雕刻任务。
- 展示进度、吞吐量和预计剩余时间。

验收标准：

- 文件雕刻不依赖有效分区表。
- 输出目录必须位于源磁盘之外。
- 应用重启后可以恢复任务状态。

### 阶段 8：镜像制作、SMART 和风险分诊

目的：在变更磁盘前支持更安全的恢复流程。

功能：

- 从物理磁盘创建原始磁盘镜像。
- 校验镜像哈希。
- 支持中断后继续镜像制作。
- 在已安装时可选集成 `ddrescue`。
- 在 `smartctl` 或原生 API 可用时展示 SMART 健康摘要。
- 当源磁盘看起来存在物理风险时给出警告。

验收标准：

- 当 SMART 或读取错误提示风险时，UI 建议先制作镜像再修复。
- 镜像文件创建后可立即扫描。
- 哈希和读取错误摘要存入报告 JSON。

### 阶段 9：自动化和高级工作流

目的：让工具可用于可重复的支持流程。

功能：

- 为扫描、报告导出和计划校验提供 CLI 包装。
- 批量扫描镜像。
- 无头 JSON 输出。
- 使用显式 unsafe 标志执行脚本化恢复计划应用。
- UI 字符串本地化。

验收标准：

- GUI 和 CLI 共享同一套核心逻辑。
- CLI 破坏性操作必须要求显式标志和确认令牌。
- 批处理模式默认不执行写入操作。

## UI 路线图

UI 应从当前双表格布局逐步演进为任务导向的标签页：

- 设备：磁盘/镜像列表、元数据、健康、权限。
- 分析：分区表、警告、发现候选项。
- 恢复：恢复计划构建器和写回。
- 格式化：外置/可移动格式化和卷操作。
- 镜像：创建、校验、恢复磁盘镜像任务。
- 文件：删除恢复和文件雕刻工作流。
- 报告：导出/导入扫描和操作报告。

## 测试策略

必需测试层：

- 针对解析器、文件系统检测器、目标规范化和安全门禁的单元测试。
- 使用生成的 MBR/GPT/APFS/FAT/exFAT/ext 镜像做 fixture 测试。
- 使用命令输出 fixture 测试平台适配器，避免真实设备变更。
- 破坏性操作只针对临时磁盘镜像或 mock 命令执行器测试。
- 针对 macOS、Linux、Windows 上 USB 磁盘的手工硬件测试矩阵。

最低 CI 矩阵：

- macOS latest：单元测试、Vue 构建、Tauri 编译。
- Ubuntu latest：单元测试、Vue 构建、Tauri 编译。
- Windows latest：单元测试、Vue 构建、Tauri 编译。

## 安全要求

- 绝不能因为前端声称安全就推断磁盘可写。
- 每个破坏性命令执行前，后端必须重新分类目标。
- 除非未来 RFC 定义明确的专家覆盖模式，否则内置/系统磁盘必须被阻止。
- 每个写入操作必须生成操作日志。
- 每个写入操作必须有 dry-run 表示。
- 每个恢复输出路径必须不同于源磁盘。
- 破坏性命令不得使用 shell 字符串拼接构造；必须使用结构化进程参数。

## RFC 拆分

本文档是路线图 RFC。每个实现阶段在编码前都应创建独立后续 RFC：

- RFC 0002：平台适配器边界和磁盘模型
- RFC 0003：跨平台磁盘枚举
- RFC 0004：分析能力对齐和深度扫描改进
- RFC 0005：跨平台格式化
- RFC 0006：恢复计划构建器
- RFC 0007：分区表写回和备份
- RFC 0008：引导扇区修复辅助
- RFC 0009：文件恢复和删除恢复
- RFC 0010：PhotoRec 风格文件雕刻
- RFC 0011：镜像制作、SMART 和风险分诊
- RFC 0012：CLI 和批处理自动化

## 开放问题

- Linux 格式化应依赖系统 `mkfs.*` 工具、内置辅助工具，还是两者都支持？
- Windows 原始磁盘访问第一版应只用 PowerShell，还是直接使用 Win32 API？
- APFS 工作流的最低 macOS 支持版本应是多少？
- 是否应该允许专家模式覆盖内置磁盘保护？
- PhotoRec 风格文件雕刻应放在当前仓库，还是拆成独立 crate？
